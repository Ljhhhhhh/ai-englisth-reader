# 第一阶段 MVP 周度路线图

> **针对代理工作者：** 必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 来逐任务实施此计划。步骤使用复选框（`- [ ]`）语法进行跟踪。

**目标：** 将第一阶段 MVP 计划转化为具有周度里程碑、检查点和发布关卡的短周期交付计划。

**架构：** 遵循现有的第一阶段 MVP 实施计划，按周切片交付核心阅读循环，每周以可见成果结束。将范围锁定在 MVP 阅读循环，以保持日程风险可控，并在整个过程中验证桌面/移动端质量，而不是留到最后。

**技术栈：** Next.js 15 + TypeScript + Tailwind CSS + Prisma + SQLite + Vitest + Playwright

---

## 规划假设

- 有一名全栈开发者作为主要交付负责人
- 产品范围锁定在当前第一阶段 MVP 计划
- 可以并行准备至少 2 篇文章的样本内容
- 本阶段无登录、无 CMS、无跨设备同步
- 周度关闭意味着：代码完成、自测完成、演示就绪

## 整体节奏

- 建议总时长：**4 周**
- 节奏：周度构建里程碑 + 周度验证检查点
- 演示节奏：每周结束
- 发布目标：第 4 周结束，经过完整流程和跨设备检查通过后

## 里程碑概览

| 周      | 里程碑           | 预期结果                                               |
| ------- | ---------------- | ------------------------------------------------------ |
| 第 1 周 | 项目基础就绪     | 项目可在本地运行，具有文章数据模型，首页可显示文章列表 |
| 第 2 周 | 阅读器骨架就绪   | 用户可进入文章、遍历阶段并恢复阅读                     |
| 第 3 周 | 核心学习动作就绪 | 用户可查词、收藏、生词查看、做题并进入回顾             |
| 第 4 周 | MVP 试用就绪     | 桌面/移动端完整流程通过，异常状态覆盖，烟雾测试通过    |

## 第 1 周：基础和内容基础

**周目标：** 构建可用的项目基础，以便后续功能工作无需反复重做设置。

**主要输出：**

- 项目脚手架就绪
- 数据库和样本数据就绪
- 文章模式固定
- 首页可显示文章卡片

**工作项：**

- [x] 设置项目基础、脚本和测试工具
- [x] 构建文章内容结构和样本文章文件
- [x] 构建进度、生词、测验记录和事件的持久化基础
- [x] 构建首页文章列表
- [x] 添加“继续阅读”占位逻辑，即使尚未有进度

**第 1 周完成标准：**

- 首页可在本地打开
- 至少 2 篇样本文章可见
- 文章数据无需手动修补即可加载
- 基本测试可运行

**关注风险：**

- 文章数据形状变化过于频繁
- 设备身份方案未定
- 种子数据质量不足以支持后续查词和测验工作

## 第 2 周：阅读流程和恢复

**周目标：** 在结构层面使文章阅读容器从头到尾可用。

**主要输出：**

- 阅读页面存在
- 四个阶段可见
- 用户可在阶段间移动
- 阅读进度保存并恢复

**工作项：**

- [x] 构建引言/阅读/测验/回顾阶段壳
- [x] 添加阶段导航和进度显示
- [x] 保存当前阶段和阅读位置
- [x] 刷新或重新进入后恢复上次进度
- [x] 使桌面和移动布局均适用于阅读器壳

**第 2 周完成标准：**

- 用户可进入文章并遍历所有四个阶段
- 用户离开并返回同一阶段
- 移动视图不中断主要阅读流程

**检查点演示：**

- 显示从首页进入
- 显示移动到阅读阶段
- 显示刷新并继续阅读

**关注风险：**

- 刷新后状态重置
- 移动布局阻挡阅读
- 回顾阶段解锁规则过早混入导航

## 第 3 周：学习动作和主要闭环

**周目标：** 完成使产品感觉像“互动深度阅读”而非普通文章页面的核心动作。

**主要输出：**

- 查词功能可用
- 收藏生词流程可用
- 测验功能可用
- 回顾部分正确解锁
- 生词页面可用

**工作项：**

- [x] 为桌面和移动端构建查词面板
- [x] 添加收藏生词流程并提供清晰成功反馈
- [x] 防止重复收藏生词
- [x] 构建测验提交和答案解释流程
- [x] 仅在测验提交后解锁完整翻译
- [x] 构建生词页面，支持搜索和文章分组
- [x] 记录关键学习动作

**第 3 周完成标准：**

- 用户可点击单词立即查看解释
- 用户可收藏单词并在生词中查看
- 用户可完成测验并进入回顾
- 文章可按 PRD 规则标记为完成

**检查点演示：**

- 显示桌面查词和收藏
- 显示移动端查词抽屉
- 显示测验提交和回顾解锁

**关注风险：**

- 查词内容缺少源句
- 重复收藏规则变得混乱
- 阶段切换绕过程序解锁翻译

## 第 4 周：强化、跨设备 QA 和试用准备

**周目标：** 将功能完整的构建转化为可由真实用户测试的版本。

**主要输出：**

- 空状态和错误状态覆盖
- 响应式行为稳定
- 手动烟雾检查列表通过
- 可做出 MVP 发布决策

**工作项：**

- [x] 覆盖无内容、坏内容、收藏失败和查词失败情况
- [x] 优化桌面阅读宽度和移动触摸行为
- [x] 验证调整大小和旋转不丢失状态
- [x] 运行完整自动化检查
- [ ] 在桌面和移动视口运行完整手动烟雾流程
- [x] 准备设置和测试说明

**第 4 周完成标准：**

- 桌面和移动端完整流程通过
- 主要阅读循环无阻塞问题
- 烟雾检查列表完整
- 团队可决定开放 MVP 试用，无需进一步结构变更

## 发布关卡

仅当以下所有条件为真时，才宣布第一阶段就绪：

- [ ] 用户可从首页开始并完成一篇文章
- [ ] 用户可查词并保存生词而不丢失阅读位置
- [ ] 用户可完成测验然后查看回顾翻译
- [ ] 用户可离开并在同一设备上稍后继续
- [ ] 生词页面显示文章和源句
- [ ] 桌面和移动端均通过主要流程
- [ ] 空状态和失败状态易懂、不崩溃

## 建议周度回顾问题

每周结束时询问这些问题：

- [ ] 闭环仍是首要优先级，还是范围漂移开始了？
- [ ] 本周是否为用户创建了端到端可用的内容？
- [ ] 移动端是否正在验证，而不是推迟？
- [ ] 文章内容质量是否足以支持下一周？
- [ ] 是否有功能应被切掉而不是拖到第 4 周？

## 日程压缩规则

如果进度延误，按此顺序切掉：

1. 减少首页润色
2. 减少生词页面润色
3. 减少分析细节
4. 保持主要阅读循环、收藏生词流程、测验、回顾解锁和恢复能力完整

绝不切掉：

- 四阶段阅读器流程
- 查词
- 收藏生词流程
- 测验和回顾
- 同一设备恢复
- 桌面/移动可用体验
