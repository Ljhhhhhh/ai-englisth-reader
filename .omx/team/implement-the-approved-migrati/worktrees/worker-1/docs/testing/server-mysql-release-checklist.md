# Server + MySQL 发布验证清单

该清单补充 `docs/testing/mvp-smoke-checklist.md`，用于迁移到 MySQL、账号登录与 ECS 部署后的发布前验证。

## 自动化命令矩阵

按顺序执行并记录 PASS / FAIL：

1. `pnpm lint`
2. `pnpm test`
3. `pnpm build`
4. `pnpm prisma validate`
5. `pnpm test:e2e`

如果集成分支补充了 MySQL 专用集成脚本，也应把命令与输出附到发布记录中。

## 本地 / 预发功能验证

1. 登录：请求验证码、完成验证码登录、落回首页。
2. 同账号跨浏览器验证：
   - 浏览器 A 登录后开始阅读并保存一个单词。
   - 浏览器 B 以同账号登录后，能看到“继续阅读”和相同生词。
3. 阅读器：
   - 导读 -> 正文 -> 完成阅读流程保持可用。
   - 查词、讲解、保存单词、失败重试行为保持可用。
4. 生词本：
   - 仍按文章分组。
   - 删除 / 已记住操作在登录态下可用。
5. 生成链路：
   - 提交生成请求。
   - 轮询任务直到完成。
   - 生成文章仅创建者可见。
6. 匿名访问：确认仍允许公开访问的页面维持预期，其余受保护路径会重定向或报错。

## 部署后 Smoke

1. `GET /api/health` 返回 `200`。
2. 打开首页，确认文章列表正常展示。
3. 完成一次登录。
4. 打开任意文章并进入正文。
5. 保存一个单词，然后到 `/words` 验证它可见。
6. 提交一次生成任务并轮询到完成。
7. 检查日志中是否出现重复验证码失败、卡住的生成任务或数据库连接错误。

## 发布门槛

只有在以下条件全部满足时，才能宣布迁移完成：

- 自动化命令全部通过。
- `/api/health` 稳定返回成功。
- 跨设备同步已手工验证。
- 生成任务 ownership 已手工或自动化验证。
- 没有 launch-critical 路径继续依赖 SQLite、`localStorage` 作为 source of truth、cookie-only 持久化或文件系统文章写入。
