# 分段精读升级设计

**目标**

把文章正文区从“用户自己选择聚焦哪一段”的体验，升级成“系统带着用户一段一段读完”的体验。用户进入正文后，应该立刻知道现在读到哪里、下一步该做什么；查词、刷新、退出重进、移动端切换方向后，都应该能自然接上当前阅读进度。

**当前问题**

1. 正文区的主动作是“聚焦第 N 段”，更像功能操作，不像阅读推进。
2. 系统虽然已经会保存段落位置，但用户感知到的是“我还要管理段落”，不是“系统帮我接着读”。
3. 首页续读、正文恢复提示、正文状态提示分别在说不同的话，产品价值没有被讲成一件完整的事。
4. 现有测试和文档围绕“聚焦段落”展开，会把后续体验升级绑死在旧表达上。

**改造原则**

1. 保留“记住读到哪一段”的底层能力。
2. 弱化段落选择的功能感，强化“继续读下一段”的结果感。
3. 默认由系统突出当前段落，让“当前段落”成为阅读主线。
4. 桌面和移动端都遵守同一套阅读心智：当前段、上一段、下一段、继续阅读。
5. 文案、交互、测试、文档要一起改齐，避免出现旧叫法和新体验并存。

**设计方案**

## 1. 正文阅读主流程

正文页改成按段推进，而不是按段选择。

用户进入正文后：

1. 页面顶部明确展示当前阅读进度，例如“第 2 段 / 共 6 段”。
2. 当前段落是页面唯一主角，视觉上最突出。
3. 其他段落可以保留在页面中，但降级显示，不抢当前段的注意力。
4. 主动作改成推进式按钮：
   - 第一段显示“开始这一段”或直接进入当前段阅读状态
   - 中间段显示“下一段”
   - 非第一段显示“上一段”
   - 最后一段完成后显示“读完，进入复盘”

这样用户的主线会变成：

进入正文 -> 阅读当前段 -> 前往下一段 -> 读完整篇 -> 进入复盘

而不是：

进入正文 -> 自己判断点哪一段 -> 管理当前位置

## 2. 段落结构与导航

“段落”保留，但角色变化：

1. 段落不再是一个需要用户频繁点击管理的目标。
2. 段落成为系统推进阅读、记录进度、支持续读的最小阅读单元。
3. 如果需要保留快速跳转能力，它应该降级成辅助导航，不是每段上的主按钮。

本次升级优先做“上一段 / 下一段”的强主线，不额外引入新的目录面板，避免范围膨胀。

## 3. 续读与恢复体验

首页续读、正文恢复提示、正文状态提示统一围绕“你上次读到这里，可以继续往下读”来表达。

建议统一成下面这种价值表达：

1. 首页强调“上次读到第 N 段”
2. 进入按钮强调“继续阅读”或“继续这一段”
3. 正文恢复提示强调“已回到上次读到的位置”
4. 正文状态提示强调“当前阅读：第 N 段 / 共 M 段”

用户感知到的应该是“阅读没有断”，而不是“系统保存了 paragraphId”。

## 4. 查词与中断恢复

这次升级不能破坏现有优势：

1. 查词后仍然留在当前段上下文中。
2. 刷新后恢复到当前段。
3. 从首页“继续阅读”进入时恢复到当前段。
4. 移动端抽屉打开关闭、切换屏幕方向后，当前段保持不丢。

## 5. 文案策略

本次替换掉“聚焦第 N 段”这类偏功能导向的表达。

文案原则：

1. 用户视角，不用内部状态词。
2. 强调“继续读”“当前读到哪”“还剩多少”。
3. 少说“聚焦”“定位”这种工具感词，多说“继续”“下一段”“读完这一段”。

## 6. 测试与文档策略

测试和文档要从“验证段落按钮存在”转向“验证分段推进成立”。

需要覆盖的关键结果：

1. 正文页能按段推进。
2. 当前段与总段数对用户可见。
3. 进入下一段和返回上一段都成立。
4. 最后一段可顺畅进入复盘。
5. 刷新、续读、查词、移动端场景都不会丢失当前段。
6. 首页和需求文档中的表述已经切换到新心智。

**影响范围**

预计会影响以下区域：

1. 阅读器正文区组件与外层状态管理。
2. 首页续读卡片文案和展示。
3. 公共文案内容。
4. 端到端测试与必要的组件测试。
5. 需求文档和测试说明。

**不在本次范围内**

1. 新增完整段落目录面板。
2. 引入动画引导或复杂的阅读成就系统。
3. 改造导读、复盘的信息结构。
4. 引入跨设备账号同步。

**完成标准**

1. 正文页已经变成“按段推进”的阅读体验。
2. “聚焦段落”旧表述在正文主路径中消失。
3. 首页续读、正文恢复提示、正文状态提示全部对齐新表达。
4. 查词、刷新、重新进入、移动端切换后，都能接着当前段继续。
5. 相关自动检查通过。
6. 需求文档和测试说明里的说法与新体验一致。
